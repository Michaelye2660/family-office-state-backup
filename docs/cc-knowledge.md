## §5 经验教训库（硬教训，每条都付过学费）

1. **"master落后N commits"是幻觉**（两次）：routine会话的origin快照过时所致，master从未真落后——先 git fetch 实测,不要信会话内计数（〔M〕11）。
2. **标记提取要用整行匹配**（两次）："====文档开始===="字样会先出现在指令句子里，正文块在后——按 `strip()==标记` 整行匹配，否则截出3个字符。
3. **N8血案**：曾把专用签名私钥base64打进对话——用户整案作废（v15.34），N8由此而生。秘密值的正确姿势：用户自己生成、产品级秘密管理（环境变量）、清单只记名称与轮换路径（docs/SECRETS-INVENTORY.md）。
4. **API建的trigger缺repo sources与MCP连接器**：生产trigger一律UI建（N7第五款）；发现自己越权建了实验trigger→4分钟内自删+自首（裁决侧定性"越权+模范自首,记过不记罪"）。
5. **版本号冲突照例顺延**：用户/裁决侧给的版本号若已被占用，顺延并在版本行加注，不改不问（已成惯例，v15.42/44/46三例）。
6. **〔M〕条目插入位置要三查**（错过两次）：新条目锚错行会插到旧条目前面——插入后立即读回验证顺序。
7. **会话≠容器**：环境变量轮换后旧容器不热更新，自然回收后自愈；检测协议见SECRETS-INVENTORY.md（只看HTTP状态码，不打印值）。
8. **镜像仓push 403**：备份仓不在会话授权集时用add_repo加入即可，无需clone（push-only）。
9. **上下文压缩无损**：对话很长会自动压缩，制度记忆全在仓库——"对话为草稿，仓库为正本"（N10）不是口号，是本文件存在的理由。
10. **转写稀释不是GM专利,长文过上下文即有损**（CGM-1血案,2026-07-12·〔M〕55）：CGM-1归档EXT第2期时把674行原文压缩成212行,归档注却写"原文一字不改"——定性=转写稀释+不实保真声明,外审归档窗口覆盖查获,CGM-1认领不申辩。GM侧失败模式⑧自此在CGM侧同型实证:两侧共有,非载体特性。正确姿势:聊天粘贴长文归档一律走外审归档窗口（原文直进其上下文,零转写）;"一字不改"声明必须附同会话对源文本计算之sha1,无sha1=声明无效。
11. **Edit尾部插入必带回后继锚点标题**（2026-07-13·三次复发·〔M〕70）：用Edit在〔M〕决策日志末尾插新条目时,old_string以"…条尾。\n\n## 〔N〕系统架构（…）"为锚,若new_string结尾漏带回"## 〔N〕系统架构（…）"标题行,则该节标题被吞、新条目与〔N〕正文黏行——〔N〕节标题反复丢失(加〔M〕68一次/加〔M〕69一次,均当轮grep自查修复)。**根因=写new_string时只顾新增内容,遗忘尾部锚点须原样带回。硬规则:凡Edit锚点含节标题/结构行,new_string必原样含之;插入后立即`grep -n "^## \|^### \|^N.条"`验证结构完整,不验不算完。** 另:〔M〕条目编号插入亦须三查（§5.6原教训,〔M〕61错序为证）——两者合为"台账结构编辑三验:编号顺序/节标题完整/版本行引用与正文吻合"。

**【总则 · 断言之强度必须由凭据之强度支撑】(ADJ-0726-02②③立·2026-07-26·双侧对称·跨案适用)**

> **总则条文**:**任何断言之强度,必须由其凭据之强度支撑。** 以下四型皆为其特例,**同受本总则约束**:
>
> | 型 | 特征 | 自带之误导信号 |
> |---|---|---|
> | **全称型** | 含「全部／唯一／零／全库／一律」等范围断言 | 语气确定 |
> | **计数型** | 含「缺 N 项／共 N 件／N 次」等计数断言 | 数字看似已核 |
> | **自陈型** | 指向己方失职、对己不利 | **自带诚实信号** → 降低各层审查强度 |

>
> **执行动作(四型通用)**:落笔前须有**对应的机械命令输出**作为凭据;凭据不在,该断言**不得出现在产出中**。

## 🔴 设盲通则 · 验证元数据不得住在证据包内（ADJ-0731-46② 立·2026-07-31）

**规则原文（CGM 发现 → GM 采认并立为常设）**：

> **一个「某物已被剥除」之声明，不能住在那个被剥除之物原本所在之文件里——验证文本本身即成为泄漏。验证元数据属于封存清单与回执；证据包只应载证据。**

**两条可执行款**：

1. **证据包只载证据**。凡「**已剥除／已剔除／未复用／已核／一字未载**」之类**验证性陈述**，**一律不入证据包正文**，改入 **封存清单（SEAL-MANIFEST）与回执**。包内至多写「本包系纯证据汇编，零我方判断」这类**不指涉具体被剥除物**之通用句。
2. **理由之一般化**：**验证语句必然指涉被验证之物；在盲性场景下，指涉即泄漏。** 故本条**非本例独有**——**凡设盲之处皆适用**：压测材料、复现测试、双卡互盲、EXT 盲中继。

**🔴 案例窗（本条之出生地·教训尤深）**：`evidence-TMO-2026-07-31.md` v1 之包头曾载「本包已严格剔除我方既有 MDG 评级及其全部理由——既有档位、既有主辅机制标签、既有置信度、既有三色判、既有失效日、既有 P(错杀)/P(失守)/P(公允) 数值，**本包一字未载**」。

**该行声称我方既有评级「一字未现」，却逐一列出了它的类别构成**——**读之即知「存在一份这样形状的既有评级」**。**一句自证清白之话，本身就是那份不清白。**

**连带纪律**：**验证之可机械复核性不因本条而降低**——它只是**换了住处**。封存清单与回执须**逐项列出被剥除物与其检查命中数**（如 TMO v2 之「六项泄漏检查全零」），**使「已剥除」仍为可复算之事实，而非包内一句自陈**。

## ⚙️ 执行侧工具纪律 · 反引号与引号之两次损文（CGM-G4·2026-07-31·自记）

**同一会话内两次因 shell 引号处理而损文，皆当轮捕获并补正，留痕不删：**

1. **commit message 内含英文撇号与引号** → `git commit -m "...every figure carries an as-of timestamp..."` 被 shell 拆成多个 pathspec，**提交未成**。改用 `git commit -F <消息文件>` 后一次通过。
2. **`python3 -c "...改写含反引号之中文..."`** → 反引号触发**命令替换**，把两个文件名当命令执行并**吃掉原文**（`签收片 ADJ-0731-13 与 ADJ-0731-03-to-06-and-10` 被吃成 `签收片与`）。

**🔴 立为纪律**：**凡改写含反引号（\`）、单引号、双引号之中文内容，一律走 heredoc（`<<'PY'` 单引号定界符，禁止插值）或写入脚本文件后执行；不得用 `python3 -c "..."` 或 `git commit -m "..."`。**

**教训之一般化**：**这两次都不是判断错，是载体错**——内容本身正确，毁于传输层。**故落库后之「结构四验」不能只验内容对不对，还须验「写进去的是不是我打算写的那一串」**；本仓既有之乱码两类扫描即属此类，本条系其同族补充。
