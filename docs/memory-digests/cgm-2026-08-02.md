## 一 · 🔴 本场次之实：**三条独立信号互相印证，而它们同源**

第 0 步照唤醒句执行 `git fetch origin master && git checkout master && git pull origin master`，得：

```
+ fd1d058...17949fa master -> origin/master  (forced update)
Your branch and 'origin/master' have diverged,
and have 50 and 50 different commits each, respectively.
```

三条信号：**各 50 commit 分叉** ／ **`merge-base` 返回空**（无共同祖先）／ **fetch 明标 `forced update`**。

**它们看起来互相印证。** 而且 `forced update` 那一行印出的旧值恰是 `fd1d058` ——本地 HEAD 本身，**读起来正像「远端把你脚下这一笔重写掉了」**。本仓红线第 1 条就是「永不 force-push、永不重写 master 历史」，所以这个读数指向的是一件很严重的事。

**查因＝`.git/shallow` 存在，全库仅 50 个提交。** 两侧各自被 `--depth 50` 截断在不同位置，于是：共同祖先落在截断线之外 → `merge-base` 算不出来 → git 只好把两边各 50 笔全报成「独有」→ 50/50。**`forced update` 同理，是浅 fetch 语境下的 ref 更新标记，不是真的历史重写。**

`git fetch --unshallow` 后同一组命令复算：**`merge-base` ＝ `fd1d058` ＝ 本地 HEAD**；本地是 `origin/master` 的**直系祖先**，1069 → 1154，**只是落后 85 个 commit**。`git merge --ff-only` 快进，**零内容丢失、未 force-push、未重写历史**。

### 何以这一条与 G5 那次要分开记

G5 在 2026-08-01 记过浅克隆（`part4`），**那次坏在读数假绿**：逾时限 48 静默变 0，一张比昨天更好看的绿表。**本次坏在别处——它长得像一次真实的分叉。**

> **假绿骗你「没事」；这一次骗的是「有事，而且是那件最严重的事」。**

**而它更阴的地方在于：若照分叉去处置，两条路都错。**
- 判「远端重写了历史、本地才是对的」→ 强推或重置 → **丢掉远端那 85 个 commit**（其中就有本席要读的交接书）；
- 判「两边都要保」→ merge → **造出一套重复历史**，把 85 笔各来一遍。

**没有一条路是「稍微不准」，两条都是实质性破坏。** 而促成这个判断的三条信号，**每一条单看都是硬证据，三条一起看还互相印证** —— 它们只是碰巧同源。

**一句可带走的**：**互相印证的多条信号，若共用同一个前提，其印证力等于一条。** 本仓已有的说法是「先证地面是真的，再信尺上的数」；**本次给它补一格：地面不真时，尺子不是读错一个数，是整张图都自洽地错。**

**处置之边界**：`tools/_repo-depth-guard.sh` 现挂在四个**读数类**器上（G5 立）。本次暴露的是**分叉类判断**同样吃这个前提。**本席只登记，未擅改该器** —— 判据正本系单点，改它属判断类，且本席正是受益方（改了显得本席就位更利索）。**呈裁，不自办。**
