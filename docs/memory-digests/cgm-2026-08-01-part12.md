## 四 · 🔴 新捕一处判据缺陷（**本席自捕·第四验之花式串扫描**）

手敲 `grep -cP '[À-ÿ]{2,}'` 得 **57**；正本 python 路（`signoff-verify.sh:113`）同文件得 **0**。
对照组更露骨：`tools/_repo-depth-guard.sh`（本仓自造之纯净文件）手敲得 **47**。

**成因＝locale。** 会话 `LANG`／`LC_ALL` 皆空 → grep 走 C locale 按**字节**解释模式串；
而模式 `[À-ÿ]` 本身之 UTF-8 编码被读成一个**覆盖一切 UTF-8 续字节**的区间 → **每段中文皆命中**。

**实害＝零**：`adj-archive/` 六份写有该读数之回执逐份查过，**皆书「命中零」，即皆走 python 正本路，无一份被污染**。

**🔴 其方向与浅克隆守卫相反，须分开记**：
深度守卫之坏是**假绿**（该红不红）；本缺陷之坏是**假红**（47／57／217）。
**假红看似安全，其实更阴 —— 它把人训练成「那个数一向不准」**，
而第四验立规之全部意义，**就是让一次真命中不被当噪声放过**。
（同内审官 §丙-3 就丙5 假红所书之理由。）

**处置**：立单一判据正本 `tools/_text-integrity.sh`（照 `_repo-depth-guard.sh` 体例：为哪次事故而立／不核什么／死法与检出法）；
**外挂检出法＝`internal-audit.sh` 自检4**，每日跑「手敲式 vs 正本式」比对（本日：正本 0 ／ 手敲 232）；**反向实测过。**

**🔴 并有一处当场兑现**：本轮台账条初稿直书了那两个测试字符，**落库前扫描即命中 1 处，命中者正是那一条自己**
—— **「判据档自身不入其所判之扫描面」之第四例，而这一次犯者是本条。** 已改为以码点称之。
