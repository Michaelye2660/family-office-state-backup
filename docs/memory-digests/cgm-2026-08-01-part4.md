## 二 · 🔴 本场次之实：**我拿到的第一张表是绿的，而它绿得比昨天好看**

`signoff-queue.sh` 首跑：**龄分布 ≤3 日 84 件·逾时限（代理判）＝0·🟢 无逾时限件**。
前代 G4 **同一日、同一 HEAD `fd1d058`** 之实测：**36／30／18·逾时限 48**。

**同一把尺、同一份数据、同一个 commit，两个读数。**

查因＝**换代所开之新容器，其仓库克隆系浅克隆**：`is-shallow-repository`＝`true`／全库仅 **50** 个提交／浅边界 `abd10e3`（2026-07-31T14:05Z）。
于是 `git log --diff-filter=A -- <回执>` 对**一切早于浅边界之文件**一律返回该边界提交 →
全部回执之「入队时点」被压成同一日 → 龄全部 ≤3 日 → **逾时限 48 静默变 0**。

`git fetch --unshallow origin` 后，**同器、同 commit、同参数**复跑：**36／30／18·逾时限 48**。

### 何以这一条值得单独记

1. **它坏掉时的表面，是一张格式完整、计数齐全、每一栏都在、且比昨天更好看的绿表。**
   ——正是交接书 §五-1 之共性；**惟这一次坏的不是判据本身，是判据所依赖之环境前提，而全库无一处断言过它**。
2. **本仓已记过一次同族**（〔M〕467④·relay 仓 `--depth 1` 之「一次加入 90 余文件」假象）。
   **差别**：那次落在**只读**之中转仓、**当场识破**；**这次落在主仓之治理闸上，默认方向是绿的**。
3. **它不是偶发，是换代之常态前提** —— **每一次 CGM／GM 换代都会重新开一个新容器**。
   **换言之：每一个继任实例的第一张日对账，都可能是假的，而且假在对自己有利的方向。**
4. **差一点它就被我写进库里**：本席首跑 `daily-recon.sh` 已把「②b 逾时限 0·🟢」写进工作树之 `docs/daily-recon/2026-08-01.md`——**是先去比对前代读数，才没让它落库**。

## 三 · 处置（**当轮做成能被检出的东西**·照交接书对下任第 3 句）

- 新立 **`tools/_repo-depth-guard.sh` ＝ 单一判据正本**（**不复制第二份**·照对下任第 2 句）；文件头载「为哪次事故而立／它不核什么／已知波及面」。
- **机械枚举波及面**（`grep -l "git log\|--diff-filter" tools/*`）→ **四器全部挂核**：
  | 器 | 浅克隆下会怎样 |
  |---|---|
  | `signoff-queue.sh` | 入队时点压成边界日 → **逾时限假绿** |
  | `activate-epoch.sh` | 声明件之首次加入 commit ＝ **写入台账之 ACTIVATION_SHA** → **取到一个错的、且看起来正常的哈希** |
  | `daily-recon.sh` | 源⑦b 覆盖核之时点与计数失真（并新增**源⓪ 历史深度前置核**） |
  | `signoff-verify.sh` | **真在史之 commit 被报成「不在史」** —— 而该语义在本仓近于篡改立案，**一个环境缺陷会被读成一次事故** |
- **四器一律 fail-closed**：**不出读数，优于出一个看起来完整的绿表。**
- **本器不自动修复**，不代跑 `--unshallow` —— **一个会自己把前提改掉的前置核，等于没有前置核。**
- **正反双向实测留痕**：正向＝本仓 unshallow 后判过；**反向＝以一个真浅克隆（`/workspace/research-review-relay`·`--depth 1`）实跑同一判据，确被拦下**。
  **不以「本仓现在是绿的」充作「判据会红」之证据** —— 这正是本仓「零命中默认先疑扫描坏了」之同一条纪律。
