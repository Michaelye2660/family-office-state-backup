## 1. 结论档位

**MDG-4 深沟**

Microsoft 的企业入口、套件分发、开发者生态、合规数据层与全球云基础设施形成相互强化的结构优势，且已出现用量计费后企业席位仍增长、E7 快速成交与高价组合上移等已观测机制证据；但当前仍缺 Copilot 续订率、流失率、去捆绑采用率及 AI 基础设施单位经济性，故不能把由默认分发、捆绑与资本补贴支撑的稳定全部记作自然粘性，也不足以进入 MDG-5。唯一须盯死的长期威胁是：**AI 商业化在去除默认分发、套件捆绑与高资本投入后，能否保持独立续订性与单位经济性。** [B1][B2][B3][B7][C1][D1][D2]

## 2. 关键理由

1. M365 商用席位仍扩张、Copilot 付费席位与净新增显著上行，并出现多家超大规模部署，说明企业工作流入口正在向 AI 层延伸，但大型部署与 E5／E7 打包并不能直接等同于自然粘性。[B1][C1]
2. GitHub 拥有庞大开发者网络，GitHub Copilot 在切换至用量计费后企业席位与消耗式收入仍增长，且 agent 已进入大量 pull request，构成强于单纯默认分发的使用机制证据。[B2]
3. Copilot／E5／E7 推动 ARPU 与高价档位组合上移，E7 推出后迅速获得数百万席位，显示定价与交叉销售能力已被客户吸收；但其中仍混有套件捆绑，不能全部计作单品定价权。[B3][C1]
4. 数据中心快速扩张、剔除 OpenAI 后的订单与 RPO 仍增长，说明需求并非完全依赖单一客户；但 RPO 属滞后读数，且 capex、单位算力成本与维持／扩张拆分缺失，不能据此否定领先端的回报风险。[B5][B6][B7][C2][D1]
5. M365 席位增速明显低于收入增速，且部分收入受确认时点影响；这支持“护城河仍深、价值捕获增强”，但也提示增长正更多依赖提价与组合上移，必须用续订与去捆绑数据验证。[B1][B3][C3][D2][D4]

## 3. 可证伪条件

### 降级至 MDG-3 的触发信号

- Copilot 付费席位连续两个季度净减少，或公司披露的同 cohort 续订率低于 80%。[B1][D2]
- 在允许客户单独采购、取消默认启用或缩小 E5／E7 捆绑后，Copilot 活跃使用量或付费席位在两个连续披露期下降超过 20%。[C1]
- GitHub Copilot 用量计费实施后，企业席位与消耗式收入连续两个季度同时下降，或涉及 agent 的 pull request 占比降至四分之一以下。[B2]
- M365 商用付费席位连续两个季度零增长或负增长，而收入增长仍主要由 ARPU、合同确认时点或提价驱动。[B1][B3][C3][D4]
- 公司披露剔除 OpenAI 及其他前沿模型公司后，Azure 订单或 RPO 增长降至个位数，且新增数据中心利用率或单位算力成本未改善。[B5][B6][B7][C2][D1]

### 对称升档至 MDG-5 的条件

- 披露 Copilot 至少两个完整续订周期的 cohort 数据，续订率持续不低于 90%，且在明确提价后仍无显著流失。[B1][B3][D2]
- 在无默认启用、可单独采购且不依赖 E5／E7 捆绑的客户样本中，Copilot 席位、活跃使用量与续订率仍保持稳定或上升。[C1]
- GitHub Copilot 在用量计费下持续扩大企业席位、消耗收入与 agent 工作流渗透，同时开发者净迁移保持为正。[B2]
- 公司披露 AI 数据中心单位算力成本下降、利用率提升，并能区分维持性与扩张性 capex，证明基础设施优势可在不依赖持续补贴的情况下自我强化。[B5][B7][D1]

## 4. 趋势成分处置口径

**已把“正在增强”读入档位，但只读到 MDG-4，未读到 MDG-5。** 领先端的 Copilot 净新增、GitHub Copilot 用量计费后的增长、agent 工作流渗透和 E7 早期采用均显示企业与开发者关系正在增强；与此同时，M365 席位低增、Copilot 留存缺失、Xbox 当前重置及资本开支单位经济性缺口构成弱化或未证实成分。[B1][B2][B3][B4][B7][D1][D2][D4][D6]

本卡不以收入、RPO 等滞后总量尚稳来否定领先风险；对所有可能依赖默认分发、捆绑、补贴或提价补偿的稳定，均单独折价处理，不记为自然粘性。[B6][C1][C2][C3]
