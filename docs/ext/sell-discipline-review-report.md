## 总结结论

本题需要的不是一套“判断股价高低、猜测未来涨跌”的卖出系统，而是一套 **持有资格审查制度**：

> 只要一个仓位仍满足事实可验证、合法经营、持续偿付、经济基础未被证伪、治理未越过红线、且仍符合组合风险约束，就默认继续持有；一旦失去持有资格，则按预先锁定的规则降低或清除敞口。

这套制度应当非常稀疏。永久资本最大的制度优势是可以不因价格波动被迫交易；因此不应把价格波动重新包装成机械卖出信号。但永久资本并不等于永久持有某一法律实体。事实可能失真，经营许可可能消失，偿付能力可能断裂，治理者可能侵害资本，组合也可能因单一风险暴露而失去韧性。这些都需要卖出纪律。

我建议采用七类判据：三类“一票否决”判据、三类可累积的公司层面判据，以及一类组合层面判据。七类是我认为足以覆盖相互独立的失败模式、又不至于造成指标泛滥的最小集合。更少会把不同风险混在一起；更多则容易制造虚假的精确性和过度交易。

## (a) 判据基础

### 1. 判据应建立在“继续持有资格”上

卖出判据的基础应当是以下三层，而不是单一指标：

1. **不可接受状态**：事实基础不可信、核心经营权消失、偿付义务实质违约；
2. **可验证的持续恶化**：最初投资论点被预先定义的可观察事实证伪，或财务韧性、资本治理持续恶化；
3. **组合角色失效**：即使公司本身没有恶化，其规模或共同风险暴露已破坏组合的抗系统性风险目标。

最初投资论点可以作为基础，但只能在被改写成可观察、可计算、带期限的“维持条件”之后使用。未经操作化的叙事，例如“管理层优秀”“护城河深”“长期空间大”，不能成为机械判据。

### 2. 为什么排除股价下跌

**股价下跌本身不应构成卖出理由。**

理由如下：

- 价格下跌不能区分信息变化、流动性冲击、风险偏好变化和基本面恶化；
- 把下跌设为卖出条件，会把永久资本变成顺周期资本，在市场压力最大时机械减仓；
- 它与既有的“持有仓下跌不动”纪律直接冲突；
- 如果基本面没有触发任何持有资格判据，价格下跌只改变市场报价，不改变资产是否合格；
- 如果基本面确实恶化，应由基本面或法律、治理、偿付判据触发，而不需要借价格代为判断。

价格可以触发一次 **信息复核任务**，例如短期异常波动后自动检查是否有监管文件、审计事项或违约事件，但价格不得直接改变持仓。

### 3. 为什么不把估值设为核心卖出判据

估值不宜成为核心卖出触发器：

- 不同商业模式无法用一个统一倍数比较；
- 估值依赖长期假设，难以做到真正机械且可复算；
- 估值过高可以持续很久，机械卖出会产生反复卖出、等待和重新买入的问题；
- 本组合已经有独立的买入价格门槛，“未达到买入价”不等于“已经持有就必须卖出”；
- 题面明确把错过机会视为非错误，因此没有必要为了捕捉高估回落而频繁交易。

唯一允许价格进入卖出系统的场景，是将市值作为 **组合暴露的计量单位**。例如某仓位因上涨而超过组合集中度上限时，可以机械减至上限。此时卖出的理由是组合风险过度集中，不是“价格太高”。

### 4. 为什么不能只用财务指标

单一财务指标容易被会计分类、周期、收购和资本结构改变所扭曲，也不适用于所有商业模式。财务指标必须满足三个条件：

- 与预先登记的经营驱动因素对应；
- 使用连续多个报告期，而非单期异常；
- 与现金、监管、审计或外部交易凭据交叉验证。

## (b) 具体判据设计

### 总体数据规则

每个仓位必须建立一张版本锁定的“持有资格卡”，其中记录：适用判据、公式、数据字段、来源优先级、基准期、阈值、复核频率和处置动作。阈值只能在尚未看到下一期数据之前修改；一旦发生或接近触发，不得追溯改写。

证据来源按以下顺序使用：

1. 监管机关、法院、审计师、债权受托人、独立托管人等外部主体的正式文件；
2. 法定申报文件和经审计财务报表；
3. 发行人正式公告；
4. 第三方数据库仅用于交叉核验，不得单独形成卖出触发。

不存在绝对“不可伪造”的数据。这里的目标是让任何单一责任人或管理层都无法在不留下矛盾痕迹的情况下伪装结果：原始文件须归档、计算须可复算、来源须尽量独立、文件须保存哈希值。

### H1：事实可验证性失效——一票否决

满足以下任一条件即触发：

- 最近一期年度审计意见为否定意见或无法表示意见；
- 审计师公开说明因管理层限制审计范围、重大会计分歧或无法取得关键证据而辞任；
- 监管机关或法院作出已生效的重大财务造假、披露欺诈认定；
- 法定定期报告在法定期限及获批宽限期后仍逾期九十个日历日。

**数据与来源**：审计报告、监管决定、法院文件、法定申报系统时间戳。

**对应风险**：认知基础失效。无法确认事实时，任何关于价值和风险的判断都不再可靠。

### H2：核心合法经营能力消失——一票否决

满足以下任一条件即触发：

- 核心牌照、特许权或经营许可被最终撤销或明确不予续期；
- 已生效的法律或监管命令禁止核心业务持续经营十二个月以上；
- 被剥夺的经营权对应最近一期经审计收入或经营利润的百分之五十以上。

“核心经营权”及其对应业务分部必须在持有资格卡中事先登记，不得在事件发生后重新定义。

**数据与来源**：监管决定、法院命令、法定牌照登记、经审计分部数据。

**对应风险**：法律存在性和经营特许权风险。

### H3：实质偿付失败——一票否决

满足以下任一条件即触发：

- 本金或利息在合同补救期后仍未支付；
- 正式进入破产、清算、司法管理或债务重组程序；
- 债权人依法宣布加速到期，且未在合同补救期内撤销；
- 审计师出具持续经营重大不确定性说明，同时可确认流动性不足以覆盖未来十二个月到期的合同性支出。

**数据与来源**：债务契约、受托人通知、法院文件、审计报告、经审计现金与到期债务附注。

**对应风险**：永久性资本损失和被动重组风险。

### A1：核心经济机制被证伪——可累积触发

每个仓位必须预先登记三个维持指标：

1. 一个需求或使用量指标；
2. 一个单位经济性指标；
3. 一个现金实现指标。

默认判定方法如下：

- 需求指标低于建仓时锁定的五年中位数的百分之八十；
- 单位经济性指标低于同一基准中位数的百分之七十；
- 三年滚动现金实现率低于百分之六十。

任意两项连续四个季度不达标，即触发 A1。

现金实现率默认定义为三年累计经营现金流除以三年累计经调整经营利润。若该公式对某类商业模式无意义，必须在建仓前从预先批准的行业附录中选择等价指标；没有适用附录则该判据记为“无法判定”，不得临时发明口径。

**数据与来源**：经审计报表、法定经营数据、监管统计；管理层自定义的非审计指标只能作为辅助，不得作为唯一来源。

**对应风险**：最初投资论点失效、需求衰退、单位经济性恶化、利润无法转化为现金。

### A2：财务韧性持续下降——可累积触发

对非受审慎监管的企业，满足以下任一组条件即触发：

- 固定费用覆盖倍数连续四个季度低于 1.5 倍，且净债务超过标准化经营利润的 3 倍；
- 未来二十四个月到期债务，大于现金、已承诺未提取授信与两倍标准化年度自由现金流之和。

对受审慎监管的企业，若监管资本或流动性缓冲连续两个报告期低于法定最低要求的百分之一百二十五，则触发。

“标准化”计算公式必须写入持有资格卡，且不得在指标恶化后改变。

**数据与来源**：经审计资产负债表、债务到期表、授信协议、监管资本申报。

**对应风险**：融资依赖、再融资失败、顺周期去杠杆和系统性流动性风险。

### A3：受托治理持续越界——可累积触发

滚动三十六个月内出现以下四项中的任意两项，即触发 A3：

- 完全稀释后股份数量累计增加百分之十五以上，且同期每股核心经营指标未至少抵消稀释；
- 未经无利益冲突股东或独立治理机构批准的关联交易，累计超过最近一期资产或收入的百分之五；
- 绩效考核口径在结果出现后被追溯修改，或已披露目标被事后重新定义；
- 在债务豁免期、付款逾期状态，或监管资本低于最低要求的百分之一百二十五时，仍进行非强制性资本分配。

**数据与来源**：股本变动登记、法定治理文件、关联交易公告、薪酬报告、债务及监管文件。

**对应风险**：代理人风险、少数资本受侵害、资本配置失控。

这类判据无法完全消除价值判断。降低随意解释空间的方法是：只允许使用上述封闭事件清单；不得以“管理层观感变差”触发；任何新增治理红线只能对未来事件生效。

### A4：组合角色失效——可累积触发，但单独要求减仓

季度末及每月月末使用托管数据进行穿透计算，满足以下任一条件即触发：

- 单一仓位连续十个交易日超过组合净资产的百分之十；
- 任一预先登记的共同失败模式风险桶超过组合净资产的百分之二十五；
- 在固定、版本锁定的压力情景中，单一仓位贡献的组合压力损失超过总压力损失的百分之十五。

风险桶只能使用事先定义的分类，例如共同融资来源、共同监管依赖、共同需求驱动或共同地域现金流，不得在触发后重新归类。

**数据与来源**：独立托管人持仓与市值、版本锁定的风险标签表、可复算的压力测试程序。

**对应风险**：集中度、共同因子、组合在系统性事件中的脆弱性。

这里使用价格只是为了计量组合暴露，而不是把上涨或下跌解释为基本面信号。

## (c) 触发之后做什么

单纯按照“触发数量”处理并不充分，因为一项事实造假不能与一项轻度财务恶化等量齐观。因此必须先区分一票否决项与可累积项，再进行数量映射。

### 一票否决项

H1、H2、H3 中任意一项触发：

- 立即将仓位标记为“不具备继续持有资格”；
- 在完成来源真实性复核后，于首个正常可交易窗口开始退出；
- 原则上在五个正常交易日内完成；若停牌或市场失灵，则在首个可实际执行窗口完成；
- 不得因价格下跌、账面亏损或等待回本而延迟。

一票否决不是因为事件一定意味着价值归零，而是因为组合的第一目标是稳定和抵御不可逆风险；在事实、合法经营或偿付基础失效时，继续承担尾部风险不符合该目标。

### 可累积项数量映射

以下所称“参考仓位”是最近一次零触发审查时记录的政策仓位，不随触发后的价格变化而重设。

| 状态 | 强制动作 |
|---|---|
| 0 项 A 类触发 | 继续持有，不作交易 |
| 1 项 A1–A3 触发 | 进入隔离状态；每月复核；启动不可暂停的升级时钟；暂不因单一首次触发卖出 |
| A4 单独触发 | 立即减至组合上限以内；这不是提醒，而是直接纠正组合暴露 |
| 2 项独立 A 类触发 | 在十个正常交易日内减至参考仓位的百分之五十 |
| 3 项及以上 A 类触发 | 在十个正常交易日内完全退出 |
| 同一项 A1–A3 连续两个定期审查周期仍触发 | 按两项触发处理 |
| 已减半后下一次定期审查仍有两项触发 | 完全退出 |

这里的“独立”是指不同风险类别，不得把同一事实拆成多项重复计数。

### 为什么不是“触发即清仓”

A 类指标可能受周期、口径和暂时冲击影响。单项首次触发直接清仓会把持有制度变成高换手制度，并放大误报成本。

### 为什么不是“触发只是提醒”

提醒没有改变风险敞口，也没有截止时间，最容易重演“规则存在但从未执行”的历史问题。本设计要求每次触发都启动不可取消的复核频率、升级时钟和明确仓位动作；因此不存在无限期观察。

## (d) 数据缺失时怎么办

### 1. 四态判定

每条判据必须且只能记录为以下四种状态之一：

- **T：已触发**；
- **N：已判定未触发**；
- **U：应有数据但无法判定**；
- **NA：按预先规则不适用，或数据尚未到法定应披露时间**。

U 与 N 必须严格分开。没有数据不构成安全证据。

### 2. 何时才算 U

只有当数据已经到应披露、应取得或应计算的时间，但未能取得、无法核对或不同来源无法调和时，才记为 U。尚未到披露期记为 NA，不得提前判为 U。

第三方数据商故障时，必须先回到法定文件和原始来源。若原始来源可得，不得因数据商缺失而记 U。

### 3. U 状态的操作规则

- 任一普通 A 类判据记 U：十个工作日内补齐；期间进入隔离状态并每周复核；
- 任一 H 类判据记 U 超过十个工作日：按两项 A 类触发处理，减至参考仓位的百分之五十；
- 七项判据中有三项及以上记 U，持续二十个工作日：减至参考仓位的百分之五十；
- 任一 H 类判据记 U 超过三十个日历日，或七项中有四项及以上记 U 超过三十个日历日：完全退出；
- 若缺失可由有记录的市场范围技术故障解释，可一次性延长十个工作日；发行人自身不披露、拒绝提供或文件矛盾不得获得延期。

多数判据无法判定时，标的不是“安全”，而是“不可验证”。对于以稳定和抗系统性风险为第一目标的组合，不可验证本身就是不能长期承受的风险状态。

### 4. 防止把不利数据改成“不适用”

NA 必须在持有资格卡建立时预先确定。任何从适用改为不适用的变更，都必须：

- 在下一期数据产生前完成；
- 由执行人与独立复核人共同批准；
- 说明替代指标；
- 仅对未来期间生效。

## (e) 如何保证它真的在运行

制度必须产生“即使什么都没有触发，也能证明已经运行”的证据。仅保存触发案例不够，因为没有记录既可能代表没有风险，也可能代表根本没检查。

### 1. 触发事件：什么时候运行

系统在以下事件发生时自动创建审查任务：

1. 每次法定季度或年度报告发布后的五个工作日内；
2. 审计师变更、财务重述、债务违约、牌照或监管决定、重大关联交易、资本结构重大变化等事件披露后的两个工作日内；
3. 每月最后一个工作日，针对组合风险判据 A4 运行一次；
4. 每月为每个仓位生成一次“心跳记录”，即使本月没有新披露、没有触发，也必须记录“已检查、无新增事件”。

### 2. 责任人

每个仓位指定三种不同角色：

- **执行人**：获取原始文件、录入数据、运行规则；
- **独立复核人**：核对来源、公式和状态，不得与执行人为同一人；
- **制度所有人**：维护规则版本、监控逾期任务，但不得为单一仓位自行改阈值。

至少实行双人控制。执行人不能自行证明自己已经正确执行。

### 3. 每次运行的具体动作

每次审查必须依序完成：

1. 从预定来源清单取得原始文件；
2. 保存文件时间戳、来源地址和内容哈希；
3. 提取持有资格卡指定字段；
4. 运行版本锁定的公式；
5. 为七项判据分别输出 T、N、U 或 NA；
6. 系统自动生成要求动作和截止日期；
7. 独立复核人签署；
8. 若要求交易，保存订单、成交和结算凭据；
9. 若无法执行，记录客观障碍，并按原规则顺延，不得人工取消。

### 4. 不可伪装的运行凭据

每次运行应生成一份机器可读记录，并写入受保护、只追加的审查账本。记录至少包含：

- 仓位匿名内部编号；
- 预定运行日期与实际完成时间；
- 触发运行的事件编号；
- 原始文件来源、文件哈希和归档位置；
- 输入字段与数值；
- 规则版本和计算程序哈希；
- 七项判据状态；
- 系统生成的处置动作与截止日；
- 执行人和复核人的数字签名；
- 订单、成交、结算或无法交易的独立凭据。

代码库中的记录必须位于禁止强制推送、要求复核批准的受保护分支。交易凭据应来自独立托管人或经纪执行系统，而不是内部制作的截图。原始监管和审计文件须保存内容哈希，确保事后无法无痕替换。

### 5. 不做的后果

- 截止日未运行：自动生成制度违约记录并通知独立复核人；
- 逾期两个工作日：复核人接管运行，原执行人失去本次签署权；
- 逾期十个工作日：相关 H 类判据记 U，并自动进入 (d) 的减仓规则；
- 十二个月内两次无正当理由逾期：责任人失去该仓位的执行资格；
- 任何人工覆盖系统动作的决定，都必须由独立治理机构批准、写明有效期，并以单独记录公开留痕；不得使用口头豁免。

这样，未运行不仅产生人事和审计后果，也会使仓位进入“不可验证”处置路径，避免制度违约长期没有资本后果。

### 6. 一个月后，外部审计者如何机械确认

外部审计者无需询问执行人“有没有做”，而是进行以下机械核验：

1. 根据法定披露时间、事件公告和月末日期，生成理论上应出现的任务清单；
2. 从只追加账本中导出实际任务清单；
3. 比较任务编号，确认完成率为百分之百；
4. 检查每项任务是否在规定期限内完成；
5. 随机抽取记录，从归档原始文件重新提取数值并复算公式；
6. 核对规则版本哈希，确认没有事后改阈值；
7. 对所有 T 和长期 U 状态，检查系统要求动作与实际订单、成交、结算凭据是否一致；
8. 检查所有豁免是否具有审批人、到期日和独立记录；
9. 即使一个月内没有任何触发，也应看到每个仓位的月度心跳记录和 A4 运行结果。

可以使用四个硬指标判定制度是否运行：

- **完整率**：已完成任务数 ÷ 应完成任务数 = 100%；
- **及时率**：按期完成任务数 ÷ 应完成任务数 = 100%；
- **可复算率**：抽样记录中可得到完全相同结果的比例 = 100%；
- **动作合规率**：已执行规定动作数 ÷ 应执行动作数 = 100%。

任何一项不为百分之百，都不是“基本运行”，而是存在明确制度缺口。

## (f) 反向质疑

题目的原始提法有一个潜在问题：它容易让人默认“一个组合总需要频繁寻找卖点”。对于永久资本，这个前提不成立。

如果所谓卖出机械是以下任何一种，本组合确实不需要：

- 因股价下跌而止损；
- 因短期估值升高而获利了结；
- 因宏观预测而择时；
- 因持仓表现落后而轮换；
- 为了证明管理动作而制造交易。

“买入时选对，然后什么都不做”是一个重要基准策略，并且应当成为本制度的默认结果：只要全部持有资格判据正常，就必须什么都不做。

但把该基准推到“永远不需要卖出”则站不住。它隐含了几个不可接受的假设：最初判断不会错、事实永远可验证、经营权不会消失、偿付能力不会断裂、治理者不会侵害资本、组合风险不会因仓位增长而集中。永久资本能承受市场波动，不代表应承受事实造假、法律失效、违约或不可控集中度。

因此，我认为设计需求应当被 **收窄而不是取消**：

> 不建立一套寻求卖点的系统；建立一套判定“是否仍有资格被永久资本持有”的系统。

如果组织无法做到持有资格卡、双人复核、原始文件归档、月度心跳和机械审计，那么宁可只保留 H1、H2、H3 三条一票否决规则，也不要建立一套条文很多但没有运行证据的装饰性制度。少而真正执行的规则，优于完整但无法证明运行的规则。
