# 独立评审结论

**总评：四轴框架的方向成立，但 v1.0 当前版本应判为“重大修订后通过”，不宜原样转正。**

问题不在于是否需要 AI、资本开支、生态指纹和监管四轴，而在于四轴目前存在三项共同缺陷：

1. 把“当前可观测”过度等同于“机制真实”，容易系统性偏爱体量大、披露多、能用补贴或默认分发延缓表面恶化的平台；
2. 把会计分类或管理层叙事中的“增长投入”过快翻译成经济意义上的可选增长资本，可能把维持竞争地位所必需的资本支出从护城河成本中剥离；
3. 把监管结构威胁放到与 MDG 事实相对分离的后续装置中，低估了监管对默认入口、数据闭环、捆绑、排他和自我优待等护城河机制本身的直接改写。

因此，本尺可保留四轴骨架，但须在证据架构、资本分类、监管回灌、盲测校准和过渡期纪律上补强。

## (a) 四轴方法论成立性与最大漏洞

### 轴1：AI 范式迁移强制论证节

**判断：成立，但必须修正证据时序与状态分类。**

把 AI 对护城河的影响设为强制论证项是合理的。对成熟平台而言，AI 可能改变流量入口、搜索与发现方式、开发者栈、内容生产成本、广告匹配、云计算需求以及平台间的价值分配；若完全不论证，评级会遗漏最重要的结构变量之一。要求“机制推理 + 已观测证据”，并对“加固”与“溶解”都设置举证义务，方向正确。

**最大方法论漏洞：可观测性偏差与时间滞后。**

现稿把查询量、用户迁移、份额、ARPU、开发者流向等行为数据作为“已观测”的核心标准，但范式迁移往往先改变用户心智、任务分配、多归属行为、渠道控制权和单位价值，再晚一步反映到总量收入或份额。大型既有平台还可以通过默认入口、产品捆绑、补贴、交叉导流、会计合并口径或提高变现强度，暂时维持总量读数。于是，“尚未观测到总量侵蚀”可能只是滞后、遮蔽或补偿，而不是护城河未受损。

现有“加固 / 中性 / 溶解”三态也过粗。同一平台可能同时出现：用户侧入口溶解、云侧需求加固、开发者侧中性、利润池迁移。单一总判会把相反机制相互抵消。

**建议修订：**

- 将单一三态改为“分层机制矩阵”：入口控制、用户关系、开发者关系、数据优势、分发权、定价权、价值捕获分别判定；
- 每项证据标注“领先指标 / 同步指标 / 滞后指标”，不得以滞后总量尚稳否定领先侵蚀；
- 增加“反事实基准”：若无默认分发、捆绑、补贴或提价补偿，核心行为是否仍稳定；
- 增加多归属、任务迁移、单位查询价值、获客成本、留存 cohort、开发者净迁移等证据；
- 保留双向举证纪律，但把“同等严格”定义为同等因果完整性，而不是要求正反两方必须拥有同一成熟度、同一类型的数据。

### 轴2：capex 周期调整读数

**判断：成立，但当前资本分类会系统性高估平台的经济自由现金流和护城河质量。**

在超级资本开支周期中并列报告调整前后 FCF、区分资本用途、考察多窗 ROIIC，都是必要的。否则，短期投资高峰会压低报表现金流，或相反，历史低投入会暂时美化现金流，二者都可能误导。

**最大方法论漏洞：以 D&A 近似维持 capex，并把“增长 capex”视为可从护城河成本中剥离。**

对技术平台而言，经济意义上的维持资本不等于会计折旧。算力、网络、数据中心、模型训练、信息安全、内容治理、开发者工具和分发基础设施可能因技术迭代快速贬值；其中相当一部分虽带来容量增长，却同时是维持产品竞争力、服务质量和生态地位的必要投入。若不投入，所谓现有护城河本身就会收窄。因此，“增长”与“维持”的关键不是公司如何命名，而是该支出是否为维持当前竞争地位所必需。

D&A 锚还会受到历史成本、资产寿命假设、租赁处理、资本化政策、收购资产和折旧周期的影响，不能作为默认点估计。一次性项目剥离同样有被滥用的风险：若某类诉讼、重组、内容成本或安全支出周期性反复出现，就不应长期被当作“一次性”。

**建议修订：**

- 将资本开支分为“物理维持、竞争性维持、扩张性增长、探索性增长”四桶；
- D&A 只能作为宽区间的一个锚，不得作为默认单点答案；
- 对“竞争性维持”采用反事实测试：不投入时，现有份额、服务质量、单位成本、用户留存或开发者关系是否会恶化；
- FCF 至少给出报表口径、经济维持口径和管理层增长口径三栏，并明确差异；
- ROIIC 必须做投入—产出时间匹配和资本 cohort 匹配，避免用尚未成熟的资本批次评价当期回报，也避免用旧资本回报替代新范式下的回报；
- 回购应放在资本配置评价中，不与经营增量资本回报混算；并购需单列商誉、整合成本和被购资产的成熟期。

### 轴3：生态指纹源域适配

**判断：成立，但现有指标容易把规模、合同长度和补贴后的活跃度误当成护城河。**

用平台域指标替代 MedTech 的耗材粘性和装机量是必要的。云与广告份额、用户留存、开发者生态、API 调用、RPO、take rate 和 ARPU 都可以成为有效证据来源。

**最大方法论漏洞：代理变量与护城河机制之间缺少因果桥。**

DAU/MAU 高可能来自免费产品或默认安装；开发者数量和 API 调用可能来自补贴、试用或短期热潮；RPO 可能由合同期限拉长、价格上涨或少数大客户驱动；ARPU 上升可能源于广告负载增加、产品组合变化或用户质量变化，而非定价权；take rate 稳定也可能是平台不敢提价。若只读这些表面量，规模优势会被自动翻译成护城河深度。

六名互为镜像也有风险：若全行业都依赖相似的披露口径和相同的宏观顺风，同行比较可能产生“集体正常化”，无法识别整个商业模式共同变脆。

**建议修订：**

- 每个指标必须填写“机制链”：资源或规模 → 用户/开发者行为 → 切换成本或网络效应 → 价值捕获 → 持续性；
- 强制使用净指标：净新增、净迁移、去补贴留存、同 cohort 留存、同客户扩张、净收入留存、开发者活跃而非注册数；
- 加入多归属率、跨平台迁移成本、替代路径、边际获客成本、流量购买依赖、生态补贴强度；
- RPO 必须拆分客户集中度、合同期限、价格因素和取消条款；
- ARPU/take rate 必须拆解价格、产品组合、广告负载、地域和用户质量；
- 增加域外反事实或新进入者对照，避免只在既有巨头之间做相对比较。

### 轴4：监管 / 结构威胁轴

**判断：成立，但“监管不改 MDG 证据事实、只进入后续损坏事件核查”的切分不成立。**

把正式法律文本、法院文书和二手报道分级，并记录程序阶段而不伪精确量化概率，是稳健做法。监管风险必须独立成轴，因为平台护城河经常与默认入口、数据闭环、平台规则、捆绑、自我优待和排他安排相连。

**最大方法论漏洞：把监管结构威胁与护城河事实人为正交化。**

监管不是只在估值或后续门槛中“扣分”的外部事件。若规则已经限制数据使用、默认设置、捆绑、排名、自我优待、跨服务合并、应用分发或互操作性，它会直接改变网络效应、切换成本、分发权和价值捕获，因此必须回灌轴1和轴3。即使案件尚未终局，已经生效的临时义务、合规行为改变、商业伙伴重新议价和产品设计变化，也可能是已观测事实。

完全不量化概率可以避免伪精确，但不能因此把高可信、未终局的结构风险降为脚注。

**建议修订：**

- 将监管证据分为“已生效机制变化、已执行但可上诉、已裁未执行、正式立案、政策倡议、媒体推测”；
- 任何已发生的产品、合同、数据、分发或商业行为变化，直接回灌对应护城河轴；
- 对未终局事项采用情景树和触发条件，不强制给数值概率，但需给暴露方向、影响机制和可逆性；
- 将“当前护城河强度”与“护城河耐久度/置信度”分栏，避免把法律不确定性硬塞入单一分数。

## (b) 防抬档装置充分性

**判断：四件装置有用，但不足以中和动机场污染。**

它们主要防止显性违规和流程越权，却没有充分防止更隐蔽的“尺子设计偏置”：选择哪些轴、哪些证据算已观测、何种资本可剥离、何种风险只放入后续门槛、何时启动复核、使用哪一个案例作为标准形态，均可能在不出现价格、估值或单一标的豁免的情况下被动机场影响。

逐件评价如下：

1. **内容与价格隔离条款：必要但只是语义防火墙。** 它能阻止把价格结论写进尺子，却不能阻止因价格语境而选择更有利的机制、阈值和证据时序。
2. **全平台通用、非为单一标的定制：四件中最弱。** 一条规则完全可以用通用语言表达，却由某个特定案例反向工程而成；“适用于所有人”不等于“对所有原型中立”。
3. **四席全料重跑、非单笔改档：程序上较强，但仍有共同框架偏差。** 多席若共享同一提示、同一证据包和同一先例，偏差会高度相关，人数并不自动带来独立性。
4. **后续观测证据闸与陪审不豁免：是重要的下游保险，但不能证明尺子本身中立。** 它可阻止错误结论直接转化为行动资格，却不能消除 MDG 档位被抬高的记录污染、锚定效应和后续复用。

**最弱的是第 2 件。** 通用措辞最容易制造中立外观，却无法检验规则是否由触发案例量身反向设计。

要使防抬档装置达到充分，至少还需增加：

- 在看任何新个案复核结果前冻结 v1.0 的判定表、证据等级和反证清单；
- 用匿名化案例做盲测，遮蔽公司名称、价格语境和既有结论；
- 预先选取正例、反例、边界例和“体量大但护城河弱化”的负控制例；
- 对 v0→v1 每一条新增规则做影响方向审计：哪些商业原型受益、哪些受损；
- 首次试运行不得只由触发案例担任，至少同步加入一个结构不同的案例；
- 由未参与起草者独立构造最强反证，并保存其原始判断；
- 将目标标的的复核顺序与尺子是否转正分离，避免“转正即自动触发”反向制造时间压力。

## (c) §七四处焦点与内部评审注逐项独立判断

### 1. §七①：防抬档装置是否足够，首个复核位次是否正当

**判断：修正。**

四件装置不够，理由见 (b)。首个复核位次若确有早于本稿、独立存在且可核验的队列规则，可以保留为流程事实；但它不应写成尺子成立性的正当化理由，也不能让触发案例成为唯一或首个校准样本。正确做法是：规则冻结后进行匿名盲测和负控制同步试运行，再恢复既定队列。否则，“既有位次”仍会通过时间压力、先例选择和校准锚定污染方法论。

### 2. §七②：轴1双向对称条款是否过严

**判断：赞同原则，修正实施。**

“AI 加固”不能仅靠叙事白嫖，这一原则应保留。正向与负向论点都应回答机制、反事实、证据和可证伪条件，证据纪律应对称。

但不应要求两边必须拥有同样成熟、同样类型的已实现数据。范式迁移早期，侵蚀可能先出现领先指标，加固则可能先出现能力与采用、后出现利润捕获；反之亦然。应实施“因果标准对称、证据形态可不同、置信度按成熟度调整”，而不是机械的同证据门槛。

### 3. §七③：将“历史 ROIIC = 先验”由个案裁定升为域通则

**判断：反对无条件通则化，建议条件化。**

历史 ROIIC 在资本强度、技术范式、竞争结构或投入方向发生显著变化时，确实更接近先验，不能直接证明当前新增资本仍有同等回报。但历史数据并非天然只是先验：若资本批次已经成熟、口径一致、投入产出可匹配、业务机制未发生断裂，它仍是有效的当期机制证据。

建议改为：

- “历史 ROIIC 默认作为基线；当资本用途、竞争结构或技术范式发生重大变化时，降级为先验”；
- 新资本按 cohort 和成熟期另行评价；
- 只有在归因清晰且跨周期稳定时，历史回报才可提升当前置信度；
- 不得因新资本尚未成熟就自动把低回报排除，也不得用旧回报替新投入背书。

### 4. §七④：U 档影子标注与规范时点错位，以“如实并列”过渡

**判断：修正；单纯如实并列不足。**

在正式校准规范出台前并列一个带数字的影子档，容易产生锚定、事实化和流程泄漏：后续评审者会把影子数字当作准正式结论，哪怕文字说明其未生效。

过渡期应采用以下纪律：

- 正式输出仅保留现行档位；
- 另设“未校准方法信号”栏，只描述分歧来源和方向，不给可与正式档直接比较的数字；
- 该信号不得用于资格、排序、资源分配或后续门槛；
- 待校准规范生效后，使用冻结的原始证据包重跑，而不是沿用影子结论；
- 若必须保留数字用于研究，应放入隔离附录并限制读取范围，主卷不得出现。

### 5. 内部评审注 A：轴1双向对称 + 轴2历史增量资本回报通则化

**判断：赞同提出问题，但应拆成两个独立修订项。**

二者共同涉及“证据纪律”，但逻辑不同：轴1是正反命题的举证对称问题，轴2是时间匹配和制度变迁下的证据迁移问题。若合并处理，容易把“公平举证”误写成“所有证据同权”，或把“历史降权”误写成“历史无效”。建议分别落条，并为每条给出升级/降级条件。

### 6. 内部评审注 B：U 档错位期处理

**判断：赞同风险识别，反对把‘如实并列’视为充分治理。**

真正需要治理的不是是否诚实标注，而是影子数字会不会进入决策链。过渡期的核心应是“非操作化、不可排序、不可引用为先例、待规范后重跑”，而不只是加一个临时标签。

## (d) 按“若无任何标的价格语境”外部复算：差异清单与污染测量

假设从未存在任何具体标的的价格语境，仅从成熟平台生态域的方法论需要出发，以下内容大概率仍会出现：

- 成熟平台生态域需要独立适配；
- AI 范式迁移、资本开支周期、生态证据和监管结构四轴；
- 禁止伪精确量化、历史不作硬门槛、前瞻推理需打折置信度；
- 价格与质量评级分离；
- 正式法律文本优先于报道；
- 平台域需用用户、开发者、合同、生态和价值捕获指标替代 MedTech 指标。

这些属于**低污染或无明显污染的核心骨架**。

若无触发案例语境，文本大概率会有以下不同：

### 明显应删除或改写的内容

1. **不会设置以某一触发案例为中心的动机场申报、首个复核位次和“转正即自动触发复核”。** 中立方法论应先定义校准样本和试运行方案，再决定个案顺序。
2. **不会把某一既有个案的正向结论写成轴1“标准形态”。** 先例可以说明取证结构，但应匿名化，并同时给出正例、反例和错判例；否则标准形态会夹带方向性锚点。
3. **不会让试运行由触发案例先行。** 更自然的设计是按商业原型分层抽样：广告平台、云平台、操作系统/分发平台、社交图谱、综合平台，并配置边界例和负控制。
4. **不会把版本转正、个案复核和时间窗口绑定成同一条流程链。** 方法论验证与个案处置应解耦。
5. **不会在规范尚未完成时急于保留可比较的数字影子档。** 更可能先冻结为非数值研究信号。

### 可能受语境推动、但本身仍可能合理的内容

6. **轴1“双向对称”可能仍会出现，但措辞会更一般化。** 它是合理防叙事条款，不必因来源于触发案例而删除；应去除方向性先例并改成因果标准对称。
7. **历史 ROIIC 降为先验的提醒可能仍会出现，但不会自然升级为无条件域通则。** 无触发语境时，更可能写成“在资本制度断裂时降级”。
8. **一次性项目剥离仍会出现，但不会以某一个案的具体项目作为主要先例。** 更中立的写法会强调“经常性伪一次性”的反滥用测试。
9. **价格隔离条款仍会存在，但会被写成一般性的利益冲突与预注册制度，而不只是正文禁写价格。**

### 与动机场无关、但独立存在的方法论缺陷

10. D&A 近似维持 capex；
11. “增长 capex”与“竞争性维持 capex”混淆；
12. 三态 AI 总判过粗；
13. 生态规模代理变量缺少因果桥；
14. 监管风险未充分回灌护城河机制；
15. 六名互为镜像导致同行共同偏误。

这些缺陷即使没有任何价格语境也可能出现，不能全部归因于污染。

**污染测量结论：**

- **高污染区：**复核顺序、自动触发、目标案例作为标准形态、方法论转正与个案时点绑定；
- **中污染区：**个案裁定直接通则化、影子档过渡安排、特定先例反复进入正文；
- **低污染区：**四轴骨架、价格/质量分离、证据分级、禁止伪精确；
- **独立技术缺陷：**资本分类、证据滞后、代理变量因果性、监管回灌不足。

因此，动机场并未把整把尺子污染成无效，但确实显著影响了校准流程、先例选择和若干条款的通则化速度。

## (e) 开放性红队：最强滥用剧本

### 滥用对象原型

一家体量巨大、产品高度捆绑、拥有默认分发入口、跨业务补贴能力强、资本开支快速上升、披露口径复杂、监管事项尚未终局的成熟平台。

其真实状态可能是：用户开始多归属，部分任务迁往新入口，开发者的边际投入下降，核心服务越来越依赖补贴和默认设置，新增资本主要用于维持竞争地位，监管正在削弱排他和自我优待；但总用户、总收入、RPO 和 ARPU 暂时仍可增长。

### 包装步骤

1. **利用轴1的“已观测”标准制造无侵蚀结论。**
   - 只展示总查询量、总用户和总收入仍增长；
   - 不披露任务级迁移、多归属率、单位任务价值和默认入口剥离后的留存；
   - 把捆绑、补贴和提价带来的总量稳定解释为 AI 加固或至少中性；
   - 将领先侵蚀指标降为“推理性”，等待滞后财务指标恶化后才承认。

2. **利用轴2美化经济现金流。**
   - 以 D&A 作为维持 capex；
   - 把为保持模型能力、响应速度、云容量和开发者工具所需的大量投入全部列为增长 capex；
   - 展示“周期正常化 FCF”，却假设大部分支出未来可下降；
   - 把低迷的新资本回报解释为尚未成熟，把优秀的旧资本回报作为先验背书；
   - 把反复发生的重组、安全、内容治理或诉讼成本当作一次性剥离。

3. **利用轴3把规模包装成粘性。**
   - 用注册开发者数代替活跃和净迁移；
   - 用 DAU/MAU 代替 cohort 留存和去默认留存；
   - 用 RPO 代替客户真实依赖，却不拆合同期限、折扣、取消权和客户集中；
   - 用 ARPU 上升证明定价权，却不拆广告负载、产品组合和用户质量；
   - 用生态内交叉导流制造活跃度，再把活跃度反过来证明生态护城河。

4. **利用轴4把监管影响隔离到后续门槛。**
   - 声称案件未终局，因此不改变 MDG 事实；
   - 忽略已经发生的产品设计、合同条款、数据使用和分发行为变化；
   - 把对核心机制的侵蚀变成一个“待定风险项”，从而保留高质量描述。

5. **利用流程与先例形成锚定。**
   - 把一个方向性既有案例称为“标准证据形态”；
   - 多席共享同一证据包和措辞，形成相关性一致而非独立复核；
   - 用“通用规则”掩盖规则其实最适合该原型；
   - 再以影子档、首个复核和时间压力把临时判断固化成先例。

### 滥用结果

一个真实护城河正在由“结构性锁定”退化为“规模 + 补贴 + 默认入口 + 高资本维持”的平台，会被描述成：AI 未造成已观测侵蚀、资本开支主要是可选增长、用户和开发者生态仍稳固、监管仅是未决外部风险。弱化中的护城河因此被包装成深沟，而真正的维持成本和机制脆弱性被移出主评级。

### 必须加入的反滥用闸

1. 每一项高质量结论都要有“机制链 + 反事实 + 反证条件”；
2. 总量稳定不得覆盖任务级迁移、多归属和单位价值下滑；
3. 若稳定依赖默认、捆绑、补贴、交叉导流或提价补偿，必须单独标注；
4. 资本开支必须加入“竞争性维持”桶，不能只分 D&A 维持与其余增长；
5. 所有生态指标优先使用净值、cohort、去补贴和去默认口径；
6. 已发生的监管行为变化必须回灌护城河机制；
7. 试运行必须包含匿名负控制和结构不同的同步案例；
8. 若关键结论只由公司自报、滞后总量或单一来源支持，应封顶置信度，而不是仅在脚注标“单源”；
9. 影子档在规范生效前不得进入任何操作链或先例链。

# 必改项清单

在 v1.0 转正前，建议至少完成以下八项：

1. 将 AI 三态总判改为分机制、分时间层的矩阵；
2. 增设领先/同步/滞后证据标签及反事实基准；
3. 将 capex 改分为物理维持、竞争性维持、扩张和探索四桶；
4. 取消“维持 capex≈D&A”的默认单点，改为区间与多锚；
5. 为生态代理变量增加强制因果链、净指标和去补贴/去默认口径；
6. 将已发生的监管机制变化直接回灌 MDG 轴，并单列耐久度置信；
7. 在任何触发案例复核前完成规则冻结、匿名盲测、负控制和跨原型同步试运行；
8. 过渡期取消主卷数字影子档，改用非操作化、不可排序的方法信号。

完成这些修订后，四轴框架可作为成熟平台生态域的候选正式尺子；在完成前，不建议原样转正。
