问题 11 ｜ stop hook 反复报"未签名 commit"，且其建议的修复方案无效  [需授权]
--------------------------------------------------------------------------------
现象：
  每轮结束时 stop hook 报警，要求对 5 个 commit 执行
  `git commit --amend --no-edit --reset-author` 或 rebase 重写。
  涉及 commit：8dc48dc、5760c05、f928da1、d8cfa10、befca2c
我拒绝执行，三条实测理由：
  (1) hook 建议的第一步是**空操作**——它让我设置 user.email/user.name，
      但实测当前配置**已经正确**（noreply@anthropic.com / Claude），
      hook 自己的输出每行也印着正确邮箱。真正的问题只是 "N" = 未签名。
  (2) hook 建议的第二步**修不好问题**——签名失败的根因是签名密钥文件为**空**：
          /home/claude/.ssh/commit_signing_key.pub  →  0 字节
          （.ssh/ 目录下仅此一个空公钥文件，无对应私钥）
      commit.gpgsign=true、gpg.format=ssh 均已配置，但无密钥可用。
      重写历史产出的仍是未签名 commit——**改写换不来签名**。
  (3) 执行它会**触犯本仓库硬禁令并波及他人提交**——5 个 commit 已全部在
      origin/master 上，改写必须 force-push，而 .claude/settings.json 对
      force-push 三种形态写死 deny：
          "Bash(git push --force*)" / "Bash(git push -f*)" / "Bash(git push origin +*)"
      且其中 3 个（f928da1、d8cfa10、befca2c）**属并行 CGM 会话的提交**，
      改写等于替他方销毁提交记录，并会使下一轮换代审计判定 master 不干净
      （台账〔M〕218①、〔M〕231② 将"无历史改写无 force-push"列为常设审计判据）。
需要你授权/处理：
  要根治，需在环境侧向 /home/claude/.ssh/ 写入**有效的 SSH 签名密钥对**
  （非空公钥 + 对应私钥），并配置 gpg.ssh.allowedSignersFile。
  配好之后的**新** commit 会自动带签名；已推送的历史维持原样不动。
  在此之前该 hook 会持续报警，属已知噪音，不必理会。
我的立场（供你复核）：
  我不会为了让 hook 显示变绿而改写共享分支上的历史——
  那是拿真实的审计完整性去换一个显示状态。若你认为应当照做，请明确下令。
