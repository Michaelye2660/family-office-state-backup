### §丙 · 🔴 本机械器之判据缺陷（**本席不改表·照章程另节书之·共 4 项**）

**🔴 丙-1 · 反引号未转义 → shell 命令替换 → 报告内容被吃掉（2 处·当日实发）**

本器运行时 stderr 报出两行，**而正表照常产出、格式完整、看不出缺了东西**：

```
tools/internal-audit.sh: line 80: constitutional-auditor: command not found
tools/internal-audit.sh: line 216: $'-0731-61⑤': command not found
```

成因＝双引号内之反引号未转义，被 bash 当作命令替换执行：

- **line 80**：`say "| **裁决侧之动作** | 本器只审 CGM 侧 | 监察官（\`constitutional-auditor\`） |"` → 表内实印「**监察官（）**」——**「谁来核裁决侧」这一格，答案被删空**。
- **line 216**：`R="…（\`-0731-61⑤\` 许代录于亲书者已不在之件…)"` → 表内实印「**（ 许代录于亲书者已不在之件**」——**丙2 之 ⚠️ 所依之规则号被删空**。

**本席机械枚举**：全文件非注释行中未转义反引号者**恰 3 行**，其中 line 256 在单引号内（安全），**真缺陷 2 处**；**其余 27 处反引号皆已正确写作 `\``**。
**故其形态不是「不知道要转义」，是「知道、做了 27 次、漏了 2 次，而没有任何检出法」** —— 与本日 UTF-8 事故（`cut -c` 读过、引用过、照样犯）**同型**。
**🔴 更要紧的一层**：**这是一个把自己报告内容删掉却不报错的失效**——**正是本器文件头所写「它坏掉时的表面是一张格式完整、每一栏都在的绿表」之本器自身实例**。

**🔴 丙-2 · 该缺陷同时是一个命令执行面**
反引号内之字串会被**实际执行**。本例执行的是不存在的命令，无害；**但该行之字串若来自库内文本（如规则号、文件名），则库内容即成为可执行输入**。**本席只陈述该结构事实，不作安全评级**。
