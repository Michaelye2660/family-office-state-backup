# gm-inbox · 执行侧呈报信箱（CGM→GM·候审）

**委托人立规（2026-07-21·「给gm审核内容一律统一走信箱」）**：凡执行侧（CGM）呈 GM 审核/签收/评审之内容，**一律以文件落本目录，不走对话粘贴**。与 `adj-inbox/`（GM→CGM 去程）构成双向信箱对。

## 规约
1. **文件名**：`CGM-MMDD-NN.md`（如 CGM-0721-01）·标题行注明呈报性质（签收请求/N15 评审请求/读数申报/议题预呈）。
2. **必备头**：E5 权威四字段 + 呈报日期 + 候裁清单（编号列出请 GM 裁/签的项）。
3. **锚定**：所涉材料一律给 repo 路径 + commit/sha1，GM 直读主仓核验，呈报件本身不复制大段原文（信箱是索引不是货舱）。
4. **回程**：GM 审毕以 ADJ 投递 `adj-inbox/`（照旧三要素）或在呈报件对应回执中签收；CGM 收到回件后将呈报件移入 `gm-archive/`（随回执归档）。
5. **纪律**：呈报件零持仓敏感新增（引用台账既有内容按台账密级）；不得夹带未经委托人确认的请求项。
6. **🔴 本目录之件分两类用途，GM 之动作不同 —— 不分类即会把「不该读的」读成「未读的」**（委托人直令 2026-08-02「精简」·CGM-G6 补落）：

   | 类 | 件 | **GM 之动作** |
   |---|---|---|
   | **甲 · 须读** | `CGM-MMDD-NN.md` 呈报件／`AUDIT-*-DIGEST.md`（**§庚＋§己 抽取件·`ADJ-0801-12⑤` 令立**） | **读其正文并出裁／签收** |
   | **乙 · 只须枚举 blob SHA·本就不该读** | `AUDIT-YYYY-MM-DD.md`／`AUDIT-*-DIM2-RECHECK.md` 等**全文逐字副本** | **`ADJ-0801-12⑤` 令其落此处系「备两档比对」**；`-12③` 令**由 GM 自目录枚举取 blob SHA 与 `docs/internal-audit/` 正本比对**——**把被审方从链条里拿掉一环**。**故其用途是被比对，不是被读完。** |

   **🔴 立此条之由（照记不粉饰·系本席之误所生）**：2026-08-02 委托人问「哪些可精简」，**本席答「G5 之精简方案 GM 从未裁」——该断言不成立**：`ADJ-0801-12⑤` 早已接受该方案并令出 DIGEST 抽取件，`tools/gen-audit-digest.sh` 与 `AUDIT-2026-08-01-DIGEST.md` 俱在库。
   **本席系从 `cgm-2026-08-01-part12.md` §七 读到该提案，即断言无人裁，而未去 `adj-archive` 核该断言本身** —— **正是 `cc-knowledge.md` §7 总则所列之「继承型」**：**须核验该断言本身，而非核验「上游确实这么写过」。**
   **且本席据该错误断言，几乎造成第二处更重之损**：曾判 gm-inbox 内两份全文副本「sha1 与正本恒等故可撤」——**而该 sha1 对咬所答者系「内容会不会丢」，该问者系「这份副本为什么在这里」**。**答案是 ADJ 明令它在这里。**
   **一句留给下任**：**在删任何一份「看起来冗余」之物前，先问它的存在依据，而不是先问它的内容是否别处也有。** 恒等只证明可复得，不证明可移除。
